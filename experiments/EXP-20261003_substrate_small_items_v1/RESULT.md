## A) 显存口径（解决 F2 扫描 0.44 vs 真实 0.24 MB/tok 之谜）

方法：8B 同一 prompt 两种路径测 peak_allocated（L=1032、4104）：

| 路径 | L=1032 | L=4104 | 增长 |
|---|---|---|---|
| **HF generate**（真实调用形态） | 16,980.7 MB | 17,727.8 MB | **0.243 MB/tok** |
| 手动全量前向（F2 扫描形态） | 17,183.4 MB | 18,529.5 MB | **0.438 MB/tok** |

- 手动前向 L=1032 峰值 17,183.4 MB **与 F2 原始 kv_peak 逐位一致** →
  证实 F2 扫描 = 全量 logits 物化路径。
- generate 路径增长 **0.243** 与 48-run 重放真实负载斜率（0.24/0.18/0.11）**完全吻合**。
- **裁定**：DES 显存记账与 swap 建模采用 **generate 路径口径**；
  F2 的 0.44/0.438 仅在声明"含全量 logits"时使用。

## B) YOLO 归因（解释 61% 未归因时间）

方法：复刻采集器的 yolo 子进程，分段计时（3 reps）：

| 段 | 中位 (ms) |
|---|---|
| 子进程 wall（总） | 5,834 |
| ├ python 启动 gap | 674 |
| ├ **ultralytics+torch import** | **1,531** |
| ├ 模型加载 | 483 |
| └ 推理 | 2,762 |

- 原 F2b "61%（4,451ms）未归因"的主体 = **import（~1.5s）+ 子进程启动（~0.7s）**；
  加上推理 ~2.8s、帧解码 ~0.7s、加载 ~0.3s → yolo 节点 ~6.3-7.5s 基本对账。
- **含义**：yolo 节点的固定开销（~2.2s/次）来自"每次起新进程 + import ultralytics"；
  常驻 worker 化或复用进程可把这部分降到近零（当前采集器为逐次起子进程）。
