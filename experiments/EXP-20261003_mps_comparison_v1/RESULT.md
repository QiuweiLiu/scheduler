# RESULT — EXP-20261003_mps_comparison_v1（C 组：MPS 对照）

**状态**：完成（2026-10-03；batch1 中 5 格因显存未释放失败，batch3 已用修复脚本补跑）。
**远端脚本 `mps_compare.py`；产物 `artifacts/mps_compare.json`。**

## 目的

回答"**单进程是否放大共置代价**"（F5 已证共置瓶颈是单进程 Python 发射串行化）。
3 种部署（单进程双流 / 两独立进程无 MPS / 两独立进程+MPS）× 4 组合（medium 档 768/128）。

## 结果（slowdown A/B；中位数，3 paired rounds）

| 组合 | single（F1 协议） | mp（无 MPS） | mps（+MPS） |
|---|---|---|---|
| 4B \| 4B | **1.98 / 2.18** | **1.02 / 1.03** | **1.03 / 1.03** |
| 3B \| 3B | **1.87 / 2.18** | **1.04 / 1.03** | **1.03 / 1.03** |
| 4B \| 3B | **1.83 / 2.25** | **1.03 / 1.02** | **1.02 / (0.84)*** |
| 8B \| 3B | **1.74 / 2.11** | **1.24 / 1.27** | **1.23 / (0.98)*** |

*括号值 <1 = 噪声（solo 基线被共享卡慢窗抬高）；MPS 与无 MPS 无实质差异。

## 结论

1. **F1 单进程协议的 ~2× 共置代价，主要是单进程 GIL 假象**：多进程下同负载 slowdown 仅
   **1.02–1.04**（4B/3B 组合，≈无代价）——与 F5"瓶颈是 CPU 发射串行化"完全一致。
2. **重模型对（8B|3B）多进程仍有真实残差 ~1.22–1.27×**：不是 GIL 假象，是真实 GPU 争用（8B 侧）。
3. **MPS 相对多进程无增益**（1.02–1.03 vs 1.02–1.04；8B|3B 1.23 vs 1.24）→ 本 harness/单卡下不需要 MPS。
4. **对 F1 表与 DES 的解释约束（必读）**：
   - F1 表语义 = "**单进程 HF harness 下的共置代价**"，**不得**当作通用多进程部署共置代价；
   - 多进程真实代价：小模型对 ≈1.02–1.04；8B|3B ≈1.22–1.27（可用作敏感性口径）；
   - 共置类机制（如 Agentix 调度）的对比结论需按部署口径分别声明。
