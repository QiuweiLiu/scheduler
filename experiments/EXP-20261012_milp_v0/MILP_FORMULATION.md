## 1. 问题界定

**串行 GPU 子问题**:2 张 GPU;同一时刻每卡至多一个计算任务;无共驻、无实测加载干扰、无主动预取、无抢占、无批处理(via `serial_v0_extension.json`,四项 profile `enabled=false` + `preemption_enabled=false` + `prefetch_overlap=false`)。

**决策**:当前就绪节点及其 H5 预测后继链的执行顺序、GPU 分配、模型冷加载、驻留与驱逐。
**冻结(参数,不可被优化器改写)**:正在运行的任务(占卡至其结束时刻)、在途加载、决策时刻的驻留模型、已到达/未到达的到达表(**不读真实未来到达**)。

**信息边界**(与实验 I 门2 同一纪律):优化器只读①决策时刻可观测状态②冻结预测产物中的 H5 链(train-only 资源估计);不读真实未执行节点、真实时长、未来到达表。

## 2. 输入与集合(全部为调度器可见量)

| 记号 | 含义 | 来源 |
|---|---|---|
| `G` | GPU 集合(索引 g=0,1) | episode `gpu_topology_mb` |
| `J` | 未完成请求(任务)集合 | 快照 job 状态 |
| `R` | 就绪 GPU 节点集合 `(j,n)` | ready 堆(`node_state=ready`) |
| `F_g` | 卡 g 的可用时刻(在跑任务的结束时刻,冻结) | `gpu.active_tasks` / finish_heap |
| `ρ_{g,m}` | 决策时刻模型 m 在卡 g 的驻留量(MB;0=未驻留) | `gpu.resident` |
| `p_i, ℓ_i, w_i` | 规划节点 i 的预测运行时长/加载时长/显存需求(p50/p50/p95) | `estimate(node, train_stats)` |
| `u_m` | 模型 m 的驻留占用(MB) | 模板 `resident_model_mb` |
| `C_g` | 卡容量(MB) | 32760 |
| `K_i` | 节点 i 的 H5 预测后继链 `[i₁…i_H]`(贪婪 top-1,≤5 步) | 冻结产物 `future_h5[0].steps` |
| `U` | 规划时间上界(见 §6) | 由上述量推导 |

**规划节点集** `P = R ∪ {K_i 中的虚拟节点}`。虚拟节点只参与规划;**永远不得作为真实 Ready 节点派发**(裁定边界第一条)。

**H5 边界节点** `b_j`:请求 j 的链上第 H 个节点(链不足 H 则为其最后一个节点)。目标只用边界节点完成时间(代理目标,**不得解释为完整请求 JCT**)。

## 3. 决策变量

| 变量 | 类型 | 含义 |
|---|---|---|
| `x_{i,g}` | {0,1} | 规划节点 i 分配到卡 g |
| `s_i ≥ 0` | 连续(ms) | i 的计算开始时刻(相对决策时刻) |
| `c_i ≥ 0` | 连续 | i 的完成时刻 |
| `y_{i,i'}` | {0,1} | 同卡冲突对 (i,i') 中 i 先于 i'(按 GPU 分组的两两析取) |
| `z_i` | {0,1} | i 是"其模型在卡 g 上的首个使用者且初始未驻留"→ 需先加载 |
| `e_{g,m}` | {0,1} | 计划在卡 g 上驱逐模型 m |

变量数:O(|P|·|G| + |P|²) 两两对 + O(|G|·|M|)。规划窗口小(2 卡、就绪+链共 ~5–15 节点),规模可控。

## 4. 目标函数(v0,按裁定:无终端价值)

```
min  J0 = Σ_{j∈J} w_j · C_{b_j}
```

- `C_{b_j}` = 请求 j 的 H5 边界节点完成时间(**预测窗口边界完成时间**);
- `w_j` = 1(v0;优先级加权留作消融);
- **v0 设 V=0**(裁定:先验证优化模型;不以与调度动作无关的固定剩余工作量充当终端价值);
- v1 再切换 `J1 = C_H5 + V̂(s_H)`(V̂ 需明确训练数据来源、至少部分随终端状态变化)。

## 5. 约束(每条附物理含义)

**(C1) 节点唯一与因果**
- ∀i∈P: `Σ_g x_{i,g} = 1`;
- 链式:虚拟节点 i_{k} 开始不得早于 i_{k-1} 完成:`s_{i_k} ≥ c_{i_{k-1}}`;首链节点 `s_{i_1} ≥ c_{i}`(i 为锚点就绪节点);
- 物理:每个节点恰好执行一次;工作流因果顺序不可改变(裁定:节点顺序不允许随机打乱)。

**(C2) 卡可用时刻与执行互斥**
- ∀i: `s_i ≥ Σ_g x_{i,g} · F_g`;
- 同卡冲突对 (i,i'): `s_{i'} ≥ c_i − U·(1−y_{i,i'})`,`s_i ≥ c_{i'} − U·y_{i,i'}`(Big-M 析取);
- 物理:任务不得早于其卡的空闲时刻;同卡任务不重叠(串行)。

**(C3) 冷加载与串行占用**
- 首用者判定:`z_i ≥ x_{i,g} − ρ_{g,m_i} − Σ_{i'先于i,同卡同模型} x_{i',g}`(线性化首用者;∀i,g);
- 加载串行:加载时间进入关键路径 `s_i ≥ (前驱完成/卡可用) + ℓ_i·z_i`,且加载期间卡不被其他计算占用(由 C2 的串行互斥 + 加载并入 i 的时长处理);
- 物理:模型未驻留则先加载(加载时长=预测 p50);同卡同模型只需一次加载;加载不与其他计算并行(串行环境)。

**(C4) 容量(按加载事件,精确到串行语义)**
- 对每个加载事件(某模型 m 在卡 g 的首用节点 i):该时刻驻留量 + i 的工作区 ≤ C_g:
  `Σ_{m'≠m} u_{m'}·[决策时驻留且未被先于 i 驱逐] + u_m + (w_i − u_m)⁺ ≤ C_g`(线性化:`[·]` 由 `e_{g,m'}` 与析取顺序表达);
- 物理:驻留模型 + 工作区增量不得超过容量(与 DES `plan_gpu_admission` 同口径)。

**(C5) 驱逐安全**
- ∀(g,m) 被计划节点使用:`e_{g,m}` 只能在"首次使用之前"或"末次使用之后"(由析取顺序约束表达);
- 物理:驱逐不得破坏正在执行/将要执行的任务(DES:仅 `active=False` 的模型可驱逐)。

**(C6) 冻结初始状态**
- 在跑任务与在途加载为参数:∀i `s_i ≥ F_g` 已覆盖;任何变量不得改写其区间;
- 物理:裁定"当前已运行的任务和加载操作不能被优化器任意重写"。

## 6. Big-M 推导

```
U = max_g F_g + Σ_{i∈P} (p_i + ℓ_i) + max_{i∈P} (p_i + ℓ_i)
```

即:所有卡可用时刻之后、所有规划节点串行跑完的**严格上界**。所有 Big-M 取 `U` 或 `U − 时长项` 的推导值(裁定:Big-M 必须由时间上界推导,禁止拍脑袋常数)。

## 7. 规划边界与截断

- 窗口 = 就绪节点 + 每节点 H5 链(≤5 步);链超过 H5 的部分不建模(边界节点截断);
- 链短于 H5:边界节点即链尾;
- 目标只到边界完成时间(代理);**不把截断误认为请求完成**(裁定 + 实验 I 短视实证)。

## 8. 求解与回退

- 求解器:`scipy.optimize.milp` + HiGHS(本机已装 scipy 1.17.1;仓库已有 `milp_sanity.py` 同接口先例);
- 预算:50 / 100 / 500 ms 三档;记录 `status / objective / best_bound / gap / solve_ms`;
- 回退:超时(≥预算)、不可行、依赖错误 → 回退冻结基线 `pdrs_resident`;记录**回退率**;
- 确定性:固定 `random_seed` 语义(HiGHS 默认确定性;记录版本)。

## 9. 动作提取与执行(与实验 I 衔接)

- **首动作** = 计划中最早开始的被选节点(并列按冻结 F0 键);映射为 `(node_key, gpu_index)`;
- 执行:复用实验 I 的 `des_rollout` 强制首动作(排序+放置),其后全部委托 `pdrs_resident`(非预知续跑);
- v0 动作集:**{排序×放置}**;预取不在动作集(串行配置关闭);驱逐动作 v1 再启用(见 §10);
- **执行合法性由 DES 保证**:若首动作不在 DES 可派发集合内,视为测试失败(T1)。
