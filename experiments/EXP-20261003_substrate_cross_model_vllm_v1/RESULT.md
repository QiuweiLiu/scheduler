# RESULT — EXP-20261003_substrate_cross_model_vllm_v1（B3：跨模型并发 vLLM 对照）

**状态**：完成（2026-10-03）。**远端脚本 `b3_cross_model.py`（经 run_vllm.sh）；产物 `artifacts/b3_cross_model.json`。**

## 目的

验证"批处理引擎模式下，异模型并发仍用 mp 表"的假设：
两个 **vLLM 引擎**（8B + 3B）同卡并发，与 HF 多进程（mp 表）对照。

## 方法

- 两个独立进程各跑一个 vLLM 引擎：8B（gmu=0.64, max_len=2048）、3B（gmu=0.31, max_len=2048），enforce_eager。
- 协议与 mp 表一致：medium 形状（768/128）；1 warmup + 3 rounds（交替 solo + 同时起跑）。
- 踩坑记录：vLLM 日志污染 stdout（协议读取需跳过非 JSON 行）；8B 在 gmu=0.62 时 KV 池仅 0.14GiB（VL 开销大）→ 0.64 + max_len 2048 解决。

## 结果

| 侧 | vLLM 双引擎 slowdown | HF-mp 参照 |
|---|---|---|
| **8B** | **1.291** | 1.24 |
| **3B** | **0.979** | 1.27 |

（solo：8B ≈ 3.6–3.8s；3B ≈ 3.3–4.2s；3 rounds）

## 结论

1. **8B 侧高度一致**：vLLM 双引擎 1.29 vs HF-mp 1.24（差 4%）→ "大模型付主要争用代价"跨引擎成立。
2. **3B 侧出现不对称**：vLLM 下 3B 几乎不受影响（0.98），而 HF-mp 下 1.27。
   → 异模型并发的"谁付代价"依部署不同：**vLLM 双引擎 = 大引擎付、小引擎免；HF 双进程 = 双方都付**。
3. **DES 建模建议**：批处理模式下异模型并发采用**不对称模型**（大模型侧用 1.24–1.29，小模型侧 ≈1.0–1.27 区间），
   或保守地对两侧都用 mp 表上限；披露两种部署的差异。

## 边界

- 单卡共享环境；3 rounds；引擎启动 ~2-3 分钟（一次性，不计入）。
- gmu/max_len 为适配双引擎共存而设（非默认），KV 池相应较小（8B: 5,632 tokens）。
