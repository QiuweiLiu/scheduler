## 3. 可辨识性发现（缺失变量量化）

- **residency（是否已常驻）**：validation 的加载事件几乎全是冷启动（214/242）；`prefix_model_reuse=True` 时通常**完全不发生加载**（load=0），仅 VL-8B 有 28 个"热加载"事件（中位 7229ms vs 同类冷加载 6764ms，样本小、差异在噪声内）。
  ⇒ 缺失变量主要决定**"是否加载"**（0 或整段加载），而这一步只能靠 model_class/上下文先验近似；这解释了 load 发生概率为什么难以进一步改进，也解释了 load 时长在冷启动内部的分布差异。
- **workload 代理**：`clip_len` 在 validation 上 100% 缺失；`query_char_len` 可用但 R0.1 已证明无增益。⇒ 工作量量级信息仍缺失。

## 4. 使用边界（给调度器集成）

**允许使用的输出**：
- 未来长度（0–5）+ 终止概率（结构）；每槽位 7 字段属性分布（q(A)）；
- 每槽位 runtime 分位数（τ=.5/.9/.95，raw ms，覆盖率已校准）；
- 每槽位加载发生概率（Brier 0.0135，ECE ≈0.03）。

**禁止/需谨慎**：
- **memory 头未训练**（不在 L_R 中）——任何情况下不得暴露；
- load 时长：可用但需标注"冷启动假设、相对 B1 约 +5% 偏差"；若调度器只关心量级/次序，风险低；
- 不要用本模型做"热加载"预测（没有 residency 输入）。
- 本审计为 validation 层；test 数字继承 J 系列冻结判定（J3 runtime Δ vs B1 = −78.1/−77.1/−64.0 ms，3/3 seeds CI 上界<0；load 时长 +6.7%/+4.7%/+4.3%），**不再重算 test**。
