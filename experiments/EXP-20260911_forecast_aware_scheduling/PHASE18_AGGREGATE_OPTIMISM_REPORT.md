## 真值口径（三条规则，全部由数据定）

1. **步骤/事件的耗时一律取 `runtime_ms`**：`api_call` 的 `timestamp_end == timestamp_start`（889/889），时间戳不可用于测区间。
2. **排除 `event_type == "run"` 的"整条流墙钟容器"**：120 条样本里容器 runtime ÷ 整文件跨度中位 = **1.000**。
   内置校验：640 个模板的"非容器事件之和 ÷ 容器墙钟" **中位 0.982**（p10 0.970、p90 0.988）。
3. **一个 artifact future slot = 一个事件（不是 agent 步骤）**：预测器监督集 7,195 个 slot 全为 `api_call`/`action`，
   **0 个容器**（锚点 `:run:1` 的 slot 是 `api_call:2`、`action:3`，即同一步骤的两个事件）。
   因此 `s_true_next_k` = **锚点之后 K 个非容器事件**，K = 预测链长度。

`next_k` = 之后 K 个非容器事件之和；`b = S_true − ΣŜ`（正 = 预测偏低）；`r = ΣŜ / S_true`；`ros` = ΣŜ/ΣS_true（ratio of sums）。

## 主结果（primary，next_k）

| τ | r 均值 [95% CI] | r 中位 | 低估率 | ratio_of_sums |
|---|---|---|---|---|
| p50 | **0.456 [0.437, 0.474]** | 0.363 | **92.7%** | 0.348 |
| p90 | **3.521 [3.285, 3.766]** | 2.174 | 6.2% | 2.020 |
| p95 | **4.905 [4.590, 5.234]** | 2.987 | 2.1% | 2.824 |

- **p50 求和系统性偏低**：平均只到真值的 46%，93% 的锚点被低估；
- **p95 求和远不是"纠偏"**：平均是真值的 **4.9 倍**（聚合口径 2.8 倍）→ 它是一个**高度保守**的估计，
  而不是把整体偏差补回来的校准器；
- 因此**"p95≈聚合纠偏"这一替代解释被否**：真值落在 p50 与 p95 求和之间（约 2.9 倍 p50 和、0.35 倍 p95 和）。

## 其它人群

- `branching`：p50 r=0.492 / p95 r=4.520，与主口径同向；
- `last_step_gpu`：p50 r=1.83（无剩余工作却仍在预测 → 过度预测），p95 r=15.7。

## 结论与限制

1. 便宜且可直接用在论文里的结论：**消费的是"保守上界"而非校准后的期望**；p50 求和不可用作期望工作量代理。
2. **限制（必须在论文中声明）**：真值是"事后观测到的墙钟 runtime"，不是改变 GPU residency 后的反事实执行时间；
   预测器训练集与 workload 视频完全不相交（0/160 重叠），全部为域外推断。
3. **未解决的上游问题**：容器事件被模拟器当普通 GPU 节点执行（占总 runtime 50.2%，见门禁
   `workload_container_double_count_20260917`）。本报告的"真值"已排除容器，与预测器监督口径一致；
   但**调度实验本身仍在含容器的 workload 上跑**，该问题会影响既有机制结论，需按审阅建议修正后重跑最小矩阵。
