# MILP-v0 v2 复审意见(顾问,2026-10-12)

> 来源:ChatGPT Web 会话「分支 · 组织汇报PPT」;提交物 = 三件套 v2(commit `f2a6972`,父 `df5508c`)。
> **复审结论:条件批准 v0a 实现,暂缓 v0b。** 保留认可:GPU 条件化排序、CPU/GPU 区分、MILPObservation 隔离、v0a/v0b 分阶段、T10a/T10b 拆分。

## 必须修正(P0)

1. **C3 冷加载索引错误(确定性数学错误)**:`z_i ≤ x_{ig}`(∀g)会使未选择的 GPU 强制 `z_i=0`。改为 **GPU 条件化** `z_{ig}`:
   - `h_{ig} ≥ y_{kig}`(∀k: m_k=m_i)、`h_{ig} ≤ Σ_{k≠i: m_k=m_i} y_{kig}`;
   - `z_{ig} = AND(x_{ig}, 1−ρ_{gm_i}, 1−h_{ig})` 四条线性约束;
   - `z_i = Σ_g z_{ig}`(每节点单卡,仍二元);
   - v0a(无驱逐、加载后持续驻留)成立;v0b 重载需另建索引。
2. **C2 时序未闭合**:定义含加载的操作起点 `a_i = s_i − Σ_g ℓ_{ig} z_{ig}`;加 GPU 预测可用时间约束与 `a_i ≥ c_predecessor`;同卡互斥统一用 `[a_i, c_i]`;**首动作必须可立即派发,不得隐式安排未来启动的动作**。
3. **C4 显存不完整**:避免初始驻留重复计数与同模型多次加载重复计数;只对对应 GPU 的执行事件激活;缓存命中时 workspace 也要检查;优先事件级驻留状态与模型集合计费。
4. **v0b 驱逐暂缓**:`plan_gpu_admission()` 有最小价值子集/指定顺序/默认全驱逐多分支,须先冻结实际执行分支;"从计划派生驱逐"≠已线性化;v0a 坚持无驱逐。
5. **观测隔离加强**:`predicted_work_ms × slowdown − elapsed` 不一定正确表示 GPU 剩余忙碌;须区分加载/计算进度与已承诺操作;禁止真实 `finish_ms`/`busy_until`/隐藏事件堆;**增加"当前运行任务真值扰动"测试**。
6. **合法动作集修正**:不得用 `dispatchable_gpus × Ready` 笛卡尔积;逐个 (node,gpu) 验证执行准入与 v0a 无驱逐条件。
7. **Big-M 修正**:现证明忽略任意空闲等待;须先构造合法参考调度,再推导并显式约束时间变量上界。

## 测试补充

双 GPU 冷加载、缓存命中显存、运行任务真值扰动、重复模型使用、CPU/GPU 混合链;**T7 独立穷举不得复用 MILP 的约束生成器**;**T10b 无驱逐完整计划回放纳入 v0a 验收**。

D2. v0b 的驱逐规则仍需要具体化

这次 v2 写明“驱逐由 DES 规则派生”，方向正确。

但是代码中 plan_gpu_admission() 存在不同分支：

传入 eviction_values：选择满足容量要求、总价值损失最小的驱逐子集。

传入 eviction_preference：按指定顺序选择需要驱逐的模型。

两者均未传入：默认驱逐所有可驱逐的驻留模型。

而 des_rollout 派发路径还可能通过 joint_evict_mode 选择不同分支。

所以需要冻结 v0b 的具体分支，并写清楚 eviction_values 的来源及每次决策的更新时机。

尤其不能在 MILP 中自由选择未来驱逐结果，然后声称它是按规则派生的。 如果未来驻留状态依赖前面的优化决策，v0b 需要实际编码该规则，或者采用外部迭代验证方式；单纯一句“调用 plan_gpu_admission()”还没有形成 MILP 约束。

因此建议暂缓 v0b，实现完成 v0a 后再独立设计。
