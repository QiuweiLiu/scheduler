# J 系列机制分析：为什么 runtime/occurrence 大幅改善而 load duration 微降（exploratory）

日期：2026-09-11。性质：**探索性诊断（validation only；未触碰冻结的 test 判定）**。数据来源：`outputs/j_series_joint_resource/runs/*/run.json` 的逐 epoch 记录 + 对 validation 的一次性推理（`.scratch/j_mechanism_probe.py`、`.scratch/j_mechanism_probe2.py`）。网页版独立分析：ChatGPT Web（bridge 会话 `6a9822da…`，2026-09-11）。

## 0. 待解释现象

冻结 test：J2/J3 的 runtime 显著优于 B1（Δ −49/−65/−30 与 −78/−77/−64 ms，3/3 seeds），load Brier 也显著更优，但 load duration 平均相对 +5.2%/+5.3%（越过 5% 容差）。即同一资源接口的"发生概率"变好、"时长"微降。

## 1. 本机探索性证据

1. **逐 epoch 轨迹：runtime 与 duration 误差强正相关（+0.88~+0.95），同向改善**。说明训练期不存在"此消彼长"；duration 的最优 epoch 是 29，而 runtime 最优在 30（选择规则选 30），选择只贡献很小一部分（val duration 差 ~5–10 PB）。
2. **同 epoch 对比** validation duration（epoch29/30 附近）：B1 283.8/266.4/257.5 vs J2 291.7/276.8/261.6 vs J3 286.6/276.7/260.0（J2/J3 差 ~1–4%）。
3. **按真实 model class 分层**（load>0，n=546/seed）：
   - Qwen2.5-VL-3B（n=346，众数类）：B1 182 → J2 202/191/176、J3 197/189/173（**一致略差**）
   - Qwen3-VL-8B（n=126）：B1 731/678/642 → J2 688/703/601、J3 670/699/599（**部分改善**）
   - Qwen3-4B（n=74）：混合
4. **按时长量级分桶**（3 seeds 合并）：short≤q25 456→448→443（**改善**）；**q25–q50 180→194→193（变差 ~8%）**；q50–q75 206→210→210；long>q75 391→401→398（略差）。→ 恶化集中在中低量级，**不是**长尾。
5. **load 发生概率**：zero-load 槽位 Brier 0.00616→0.00517→0.00492；真实 load 槽位 0.1981→0.1466→0.1339（**改善 ~32%**）。
6. **接口质量**：load>0 槽位的 model_class argmax 准确率几乎不变（0.978 vs 0.973–0.980），但预测置信度上升 0.906→0.937→0.956。
7. **训练梯度探针**（epoch1）：‖g_R‖≈4.8–5.1 ≫ ‖g_S‖1.3–2.1、‖g_B‖1.2–1.8、‖g_C‖0.3–0.4；cos(g_R,g_B)≈−0.10~−0.19。

## 2. 网页版独立分析（要点）

判断：**不是训练期多任务冲突，而是资源接口学习后的"表示重构偏移"（高置信）**。证据链：runtime/occurrence 同升；duration 与 runtime 跨 epoch 强正相关；duration 最优只早 1 epoch；恶化幅度小且集中于部分 model/bucket。

机制排序（网页版给出的概率）：
1. **共享 resource 隐性层被 runtime 主导**（~0.45）：资源梯度远大于其它任务、duration 仅 1638/21423 槽位监督；但非简单"抢梯度"——共享层学到更好的资源 embedding，同时容量偏向 runtime/occurrence，未完全保留 duration 的条件信息。
2. **q(A) 分布变硬**（~0.3）：model_class 准确率不变但置信度 0.906→0.956；duration 对 model class 敏感（VL3B 恶化）。软分布熵降低 → 资源头看到的信息熵更低、长尾组合被压缩。
3. **log1p 训练 / raw 评测尺度不一致**（~0.15）：若是主因应见 long bucket 明显恶化；实际 long +1~2%、q25–q50 +8%，更像条件分布偏移。
4. **checkpoint 选择（epoch29→30）**：~0.1，不足以解释跨 seed 稳定现象。

判别性诊断（不需要重跑 test）：D1 冻结 encoder 的 duration/runtime probe（区分 a/b）；D2 统计 q(A) 的熵/置信度/KL 变化；D3 duration 的 log-space vs raw-space、逐桶 bias 分解；D4 资源损失内部分项梯度比 g_runtime:g_occ:g_duration。

修复路线排序（网页版）：① duration 独立表示/轻量 adapter（最高信息量）；② duration 条件化增强（保留 q(model_class) 软分布 + workload scale + residency/cold proxy）；③ 资源多任务加权/PCGrad（不建议第一步）。不建议优先：单纯 log1p→raw、替换 pinball、调整 checkpoint。

## 3. 合并判断（本记录结论，供后续决策）

- 两方证据一致支持：**这不是"联合训练方向错误"，也不是典型梯度冲突**；问题在于**共享资源表示对"发生概率"与"时长条件分布"的分工不足**，叠加接口分布变硬与 runtime 量级主导。
- 本机证据进一步把"时长损失"定位为：小幅度（~2–6% 相对）、集中在**中低量级与 VL3B 众数类**、与 model_class 预测正确率无关（准确率未降）——更支持"表示/条件信息容量"而非"接口识别错误"。
- 判别诊断 D1/D2/D3 已于同日执行，结果见 §5（D1 改用头交换法；原"从零 probe"因未通过常数基线自查而弃用）。

## 4. D1/D2/D3 判别诊断结果（2026-09-11 执行；validation-only）

### D1 修正为头交换法（D1'）
原计划"冻结表示后重训 probe"未通过自查：B1 自身表示上的 probe rawPB≈834，而 B1 原始头为 284，甚至差于常数均值预测器（rawPB≈502；验证集 load>0 槽位 n=546、均值 4360ms、中位 4033ms）。判定为 probe 实现/优化问题，**弃用该结果**；改用 checkpoint 头交换（两侧共享同一模型结构与词表，资源头可直接互换）：

| seed | B1 own | J3 own | B1rep+J3head | J3rep+B1head | J2 own | J2rep+B1head | B1rep+J2head |
|---|---|---|---|---|---|---|---|
| 11 | 283.8 | 286.6 | 757.5 | 336.8 | 291.7 | 332.4 | 685.0 |
| 22 | 266.4 | 276.7 | 691.1 | 303.8 | 276.8 | 302.7 | 691.9 |
| 33 | 257.5 | 260.0 | 511.4 | 329.7 | 261.6 | 331.2 | 509.8 |

（数值=validation load-duration raw pinball，越低越好。）
- **强共适应**：J2/J3 头放到 B1 表示上大幅变差（+80%~+170%）；B1 头放到 J2/J3 表示上变差约 +17%。
- **配对后几乎不差**：J2/J3 自己的"表示+头"配对只比 B1 差 ~1–4%。
- 结论：不是"表示丢了时长信息"（自己头能用），而是**表示与头在联合训练中共同偏移**；该偏移对匹配头几乎无代价，但使表示不再兼容 B1 头。

### D2 接口分布确实变硬
load>0 槽位 q(model_class)：熵 B1 0.305–0.354 → J2 0.215–0.237 → J3 0.145–0.194；top1 0.886–0.917 → 0.927–0.935 → 0.946–0.963；边际分布 KL(B1||Jx) 仅 0.008–0.017。**(b) 作为"现象"成立；但由于准确率不变、边际分布差异小，尚不能证明它直接导致时长误差。**

### D3 log/raw 尺度问题不是主因
log 空间 duration pinball：B1 0.108–0.116、J2 0.111–0.115、J3 0.108–0.115（三变体几乎相同）；raw 空间（按槽位平均）：B1 441–484、J2 451–487、J3 438–490（差异小且跨 seed 噪声大）；逐桶 bias 无一致方向。→ **机制 (c) 证据不足**。

### 合并诊断结论
- (a) 共享资源隐性层被 runtime/occurrence 主导 → **现象层面成立**（D1' 的共适应偏移 + 梯度量级 + 监督稀缺）。
- (b) 接口变硬 → **成立但因果未证**。
- (c) log/raw 尺度 → **不支持**。
- (d) checkpoint 选择 → 仅小部分。
- 因此最合适的修复方向是"**给 duration 更独立/条件化的容量**"，而不是调容差或换损失尺度。

## 6. J4 之后的"为什么"收尾诊断（2026-09-11；validation-only）

背景：J4（duration 解耦）负结果后，用户要求回到"为什么 J3 的 load-duration 会退化"这一原始问题。

### 6.1 预测分布对比（B1 vs J3，load>0 槽位，验证集）

- **校准**：q50 覆盖率 B1 = 0.333/0.339/0.333（系统性**高估**中位数），J3 = 0.553/0.363/0.463（种子 11/33 明显更接近 0.5）；q90 覆盖率 B1 0.989–1.000、J3 0.971–0.998（都过度保守，J3 略轻）；q95 = 1.000。
- **散布**：mean(q95−q50) B1 4249–4945ms → J3 3988–4401ms（J3 分布更"收紧一点"）。
- 结论：J3 的中位数校准其实**更好**，但分布形状更紧。

### 6.2 误差变化分解（Δ = J3 − B1；配对 video bootstrap，冻结 draws）

| τ | seed 11 | seed 22 | seed 33 |
|---|---|---|---|
| 0.50 | −20.9 [−54.8, +20.5] | +7.1 [−6.8, +17.5] | +1.9 [−33.2, +33.5] |
| **0.90** | **+33.2 [+23.9, +46.5]** | **+30.1 [+21.4, +38.3]** | −0.4 [−24.4, +30.1] |
| 0.95 | −12.0 [−16.7, −6.3] | −7.5 [−14.0, +0.6] | −12.1 [−21.0, −2.1] |

→ **τ=.90 是退化主源**（2/3 seeds 显著变差），**τ=.95 反而一致改善**（3/3 seeds 方向一致），中位数基本不变。

### 6.3 类别与量级

- 按模型类别（每 seed 的 Δ pinball CI）：最常加载的 **Qwen2.5-VL-3B 一致略差**（+15.3 [+8.6,+22.7]；+7.0 [+1.8,+11.9]；+5.2 [−2.2,+11.4]）；Qwen3-4B 多数 seed 变差；**VL-8B（长尾大户）在 seed 11/33 明显改善（−61.2、−43.0），seed 22 变差（+20.6）**。
- 量级分桶（3 seeds 合并）：q≤25 改善 −13.6；q25–50 +12.3；q50–75 +4.0；q>75 +6.2。
- 集中度：退化结构 seed 间不稳定（seed11 由 top5% 槽位贡献 74% 的总差；seed22 是广泛小偏移，59% 槽位变差；seed33 总体略好）。

### 6.4 结论（"为什么"的最终答案）

1. **不是零件损坏，而是拟合位置的重新分配**：J3 把条件分布的"高尾形状"微调了——τ=.95（极端长加载）变好、τ=.90（较长加载）变差、中位数不变且校准更好；精度在类别与量级之间重新分配（VL-3B 略减、VL-8B 部分 seed 明显获得）。
2. 幅度小（几十 ms，pinball 基数 180–680ms）、结构随 seed 不稳定、在 test 上恰好越过 5% 容差 → 属于**贴线级别的分布形状偏移**，而非系统性能力退化。
3. 因此 J4（拆分/解耦）修不好是必然的：**没有单独的"坏路径"可修**；这也解释了 J2/J3 在 runtime 上的收益与 duration 的微降来自同一次表示-头共适应。
4. 未能解释的残差：为何 τ=.90 在 2/3 seeds 变差而 τ=.95 一致变好（可能与 pinball 在重尾上的分位插值/训练动态有关；需换分布参数化或换度量才可能分离）——记录为后续方向，不阻塞结论。
