## 1. 场景构造契约(compatible-future scenarios)

**定义**:给定状态 s =(episode E,snapshot @ t)。一个场景 ω = 与 s 的已观察前缀兼容的一个完整未来。

| 部分 | 处理 |
|---|---|
| **固定(前缀)** | t 时刻的完整系统状态:在途任务及其进度、就绪队列、GPU 驻留/忙碌、已到达(≤t)的全部任务 |
| **可变(未来)** | t 之后到达的任务流:任务身份(模板)、到达时间、截止期 |
| **构造法(拼接)** | 场景 ω_j = 前缀(E 的 ≤t 部分)+ **捐赠集 D_j 的"未来段"**(D_j 中 arrival > t_D 的任务,重锚定:`arrival' = t + (arrival_D − t_D)`,相对截止期保持,任务 ID 重命名);t_D 取 D_j 的同进度点 |
| **快照适配** | 重建 `arrival_heap` 指向新任务索引;过滤快照 job 行中已移除的原未来任务(捐赠任务为新 ID → 全新开始) |
| **配对性** | 同一场景内所有候选动作共享同一未来(成对比较);DES 确定性 → 完全可复现(smoke 已验证 True) |
| **兼容性要求** | 捐赠集同来源分区(同模板池);到达间隔/模型需求/时长的相关性由真实数据保留;不引入人工随机 |

**已知限制(诚实标注)**:v0 只变"到达流",不变"在途任务的剩余时长"(确定性 DES);场景数 8-12 时统计力有限;拼接是"新到达组合"级泛化,不是"全新工作流"。

## 2. 信息权限阶梯(I0-I5)与评估

| 组 | 决策者可额外知道 | 用途 |
|---|---|---|
| I0 | 无(仅前缀 + 历史先验) | 基准 |
| I1 | 当前候选请求的**真实**后续链(H5 窗内) | 单请求未来 |
| I2 | 全部活跃请求的未来**模型需求**(集合/概率) | 跨请求竞争 |
| I3 | 全部活跃请求的未来**执行时长** | 计算量 |
| I4 | **未来到达**(新任务的模型需求/时间) | 未到达需求 |
| I5 | 全部联合 | 上限 |

**评估公式(枚举,无需学习器)**:对每个场景 ω 和每个候选动作 a,用 DES 回放得 J(a,ω)(强制 a + PDRS 续跑)。
- 权限 I 下的理想决策 = 按 I(ω) 分组,每组选组内平均最优动作;期望成本 = 场景上平均;
- **VOI(I)= I0 理想成本 − I 理想成本**(I0 = 对全部场景选同一动作);
- 同时报告:各动作的条件均值/方差/排序稳定性、真实可优化空间(全信息上界)、动作变化率。

**非前视约束**:任何权限只允许读其许可的信息;禁止先看全未来最优动作再假装只用局部信息。

## 3. 实验规模与产出

- **8-12 个代表性状态**(train/dev 来源,覆盖不同积压深度)+ **每状态 8-12 个场景**(原场景 + 捐赠拼接);
- 产出:**I0-I5 信息价值对照表**(各权限的 VOI、动作变化率、排序稳定性、场景不确定性);
- 停损:若所有权限的 VOI 均不超数值/抽样误差 → 停止模型开发,交付负结果与信息价值边界;
- 预算:2 小时;holdout(ep10-19)继续封存。

## 4. Smoke 结果(已完成,1 状态 × 3 场景 × 4 动作)

- 场景构造 ✓(orig 64 任务 / donor1 67 / donor2 64);
- **可复现性 ✓**(同场景+动作重跑逐位一致);
- 成本表:同动作跨场景差 1.4 万 ms(247k~261k),但**这 4 个动作的排名在 3 个场景中完全一致** → demo VOI(full)=0.0ms(该样本中"知道场景"对选谁无帮助;全量实验将用全部 17 个动作寻找排名翻转);
- 单状态成本 ≈ 2 分钟(含 makespan 预跑);全量(10 状态 × 10 场景 × ~12 动作)预计 2-3 小时——**需要先审查,再决定是否缩减规模**。
