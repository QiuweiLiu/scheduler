**状态:** 设计冻结(运行前) · 2026-10-10
**动机(外部建议实验 C):** 回答"方法在什么条件下最有价值"。固定工作负载与执行时间分布,
只操纵**到达负载**(α)与**显存容量档位**(capacity),比较 Myopic / F0 / 主线 `pdrs_resident`。

## 1. 格与臂(冻结)

- **负载档**:到达间隔乘性 α ∈ {1.00, 0.90, 0.80}(ρ_after = ρ_before/α;0.80 = 冻结 stress v2
  标定点;变换逻辑直接复用冻结的 `scripts/preprocess/build_stress_v2_episodes.transform_episode`,
  **all_normal=True 全格统一**——去掉合成 job_index%4 优先级屏障,与 stress v2 协议一致;披露)。
- **容量档**(gpu_topology_mb,均为自然机队真实拓扑):`(24576,24576)` / `(32760,24576)` /
  `(32760,32760)`。总容量 48 / 56 / 64 GB,单调。钉死容量是**仿真反事实**(披露):
  服务时间、模型内存、模板与成员不变;只改设备可容纳集合(影响准入/驱逐/预取可行性)。
  初始驻留最大 17.5GB ≤ 24GB,24GB 格可行。
- **臂** = 3 × 9 格 × 300 集(confirm300,冻结;披露:confirm 已反复用于研究决策,
  本实验不引入新方法):`myopic`(无未来无动作)/ `sameshape_h5_p95`(F0,有预测无动作)/
  `pdrs_resident`(主线,预测+驻留动作)。同一集在 9 格中**逐集配对**(同 id,仅 α/容量变换)。
- 变换实现:运行器**内存内**确定性变换(不落 9 份数据文件);产物记录每格 episode 变换聚合
  sha256、α、容量与自然源文件 sha256 → 可复现/防漂移。

## 2. 预注册假设与判据(冻结)

- **H1(负载)**:主线的 F0 相对收益随负载升高(α 1.0→0.8)在每一容量列内**不降**;
  预注册为主指标。"收益消失"判据:α=1.0 且 32/32 格上 Δ_mean(main−F0) CI 含 0。
- **H2(容量)**:显存越紧,主线相对 F0 的收益越明显:在 α=0.8 行内,
  Δ(cap2424) ≤ Δ(cap3224) ≤ Δ(cap3232)(点估计序);最强格预测 = 高负载 × 24/24。
- **H3(动作通道)**:机制计数(驱逐/冷加载/驱逐后重载/预取)在各格的响应方向一致
  (紧容量 → 驱逐与重载↑;高负载 → 争用↑);预取的容量拒绝(新增计数
  `prefetch_capacity_failures`)随容量收紧↑。
- 全部数值:Δ vs 同格 F0,逐集配对 bootstrap 2000/seed 11;零失败硬断言(任一格任一臂
  出现失败即中止)。CI 只描述 confirm300 × 该格的冻结集内不确定性;**不做跨格显著性搜索**,
  以预注册单调序为主、点估计热力图为辅。

## 4. 披露边界

- 容量钉死=仿真反事实,不代表新硬件测量;24GB/32GB 均为自然机队真实档位。
- service class 全格 all_normal(与 stress v2 同协议);不改变模型与执行时间分布。
- (α,容量) 网格为 3×3 离散档,不做连续扫描;结论限定在网格与 confirm300 内。
- 资源契约/身份门:容量变化不影响 v7 profile 的 GPU identity 校验(仅按身份类比较)——
  已验证 v7 不 pin `gpu_capacity_mb`(validate_transition_profile 无 transition_profile)。
