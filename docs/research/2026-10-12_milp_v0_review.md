# MILP-v0 阶段一审查意见(顾问,2026-10-12)

> 来源:ChatGPT Web 会话「分支 · 组织汇报PPT」;提交物 = 三件套 + 串行配置 + 复用调研(commit `06a3637`)。
> **审查结论:暂不批准按现有公式实现;批准修订规格。修订通过静态检查后进入实现。**

## 结论要点(原文摘要)

- v0 串行环境配置:基本通过(16/16 Smoke 有效),但覆盖不足;
- H5 边界完成时间目标:可保留,须注明代理目标及适用条件;
- GPU 分配与同卡排序:**必须修正**;
- 冷加载与模型驻留:**必须重写约束**;
- 驱逐控制与 DES 执行:**必须统一**;
- 当前状态与未来信息隔离:**存在新的潜在泄漏点**;
- T1–T11 测试设计:基础不错,但部分测试无法按原方案成立。

## 六项数学修正(原文)

M1(C2 同卡互斥未与 GPU 分配绑定):现有析取约束在不同 GPU 上也强制先后,把双卡并行错限成串行。改为按 GPU 索引的排序变量 y_ikg + 激活约束:`s_k ≥ c_i − U(3 − x_ig − x_kg − y_ikg)`、`s_i ≥ c_k − U(2 − x_ig − x_kg + y_ikg)`;互斥必须纳入冷加载占用。

M2(C3 冷加载变量不成立):ρ 是 MB 值不是 0/1 标志;"先于 i"是决策依赖集合不是常量;只记首次加载会漏掉中途驱逐后的重载。改为**事件级状态转移**:R/L/E_{mgk}(驻留/加载/驱逐)且 `R_{mg,k+1} = R_{mgk} + L_{mgk} − E_{mgk}`,并限制重复加载、非驻留驱逐、执行前完成加载;事件位置必须与时间关联。

M3(完成时间未闭合):补 `c_i = s_i + p_i`;冷加载与计算分离(加载起止 + `s_i ≥ 加载完成`,仅在节点确实使用该次加载时激活);**区分纯计算时间与可能已含加载的 runtime_p50_ms**。

M4(驱逐与执行统一):v0 不允许"MILP 自由驱逐、DES 按 PDRS 规则执行"。拆为 **v0a**(仅在不需要新增驱逐的可行状态上验证排序/放置/冷加载/时间建模;其他状态显式回退,不计 MILP 成功)与 **v0b**(完整实现并验证 DES 默认驱逐规则后,再扩到所有合法准入状态)。

M5(隔离新泄漏点):建立独立 **MILPObservation 投影**;严禁使用 `GPU.busy_until`、活动任务真实 `finish_ms`、`finish_heap` 真实未来结束时间、隐藏后缀模板;**不得**从 `greedy_chain_scenario()` 的真实 pending_after 占位节点构造未来,只能用冻结预测产物生成合成节点。

M6(CPU 节点与边界):H5 链中的 CPU 节点不能一律分配到 GPU;所有纳入目标的请求必须有明确定义的规划边界。

## 测试计划修正

- **T10 拆分**:单步转移一致性 vs 完整计划可执行性;后者不能用"首动作强制 + PDRS 续跑"代替;
- **T9 修订**:v7 对比留到机制对齐后;在线求解时间单独报告;**"1ms CPU = 1ms JCT"不总成立**(GPU 忙时被掩盖、空闲时才直接延迟派发)——须注入 DES 时间推进或给有依据的估算边界;
- Big-M 推导补充证明 + 求解器状态处理;小规模穷举验证最优性;
- 首动作必须来自当前 DES 合法动作集合;无合法动作时显式等待或回退,不得直接派发预测节点。

## 修订优先级(原文)

| 优先级 | 任务 | 验收 |

当显存不足、且没有传入 eviction_preference 或 eviction_values 时，代码会选择全部可驱逐驻留模型。

这是现有 DES 的真实机制。

因此文档中的“只要满足容量就可以任意选择驱逐集合”与默认执行路径不等价。

v0 必须复现默认规则，或者明确将受限的无驱逐状态单独建模，不能让求解器自由选择一个 DES 不会执行的最优驱逐集合。

3. 求解时间不能简单等价为任务完成时间增加

T9 写了：

1ms CPU = 1ms 完成时间口径。

这个关系不总是成立。

如果 GPU 正忙，求解器耗费的 1ms 可能完全被 GPU 执行时间掩盖；如果 GPU 空闲等待调度决策，1ms 才可能直接造成派发延迟。

因此应同时报告 CPU 实测求解时间和调度收益。要计算端到端净收益，必须明确把调度决策延迟注入 DES 的时间推进，或给出有依据的估算边界，而不是直接逐请求加上求解时间。
