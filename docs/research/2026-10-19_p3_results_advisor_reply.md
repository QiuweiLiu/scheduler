3. 更重要的是训练哪些状态

我不建议均匀采集几十万个普通调度状态。

此前你们已经发现大量状态动作之间几乎没有有效差异。让模型在这些状态反复学习 PDRS，容易获得很高的分类准确率，却没有 JCT 收益。

应先区分：

没有替代动作的状态；

有替代动作但条件收益接近零的状态；

存在稳定条件收益、值得偏离 PDRS 的状态；

单次开天眼 Headroom 很大、但对未知未来并不稳定的状态。

只有第三类对学习改进策略最直接有用。第四类适合研究预测信息价值，但不适合直接作为无需未来输入的行为克隆目标。

训练可以对第三类提高采样频率，但评估必须恢复真实状态分布，不能只在精选的“高 Headroom 状态”上计算平均改善。

而且你们此前的 AV 训练集只有几十个状态，无法据此断言“增加教师数据也没有用”。但反过来，也不能认为数据量大就必然可以突破可观测性限制。

4. 学生实验的批准边界

我建议批准一个独立的 Student Feasibility Gate，先不进行大型神经网络训练。

首先从 train 来源构造多未来反事实动作成本数据，明确 episode、模板和到达样本来源。先用轻量树模型、成本敏感排序或简单 MLP 试验，选择阈值只能使用训练侧交叉验证。

然后在未参与模型与阈值选择的 development episode 上运行完整在线闭环 DES，而不仅是报告离线动作分类准确率。最后才考虑使用已经封存的验证来源做一次冻结后的正式测量。

这里尤其要记住：此前定义的 Arrival-Holdout 主要检查新到达流，并不是严格的未见工作流模板测试。不要把两种泛化能力混为一谈。

停损条件： 如果学生对 PDRS 的偏离在离线数据中有预测优势，却在闭环执行中无法稳定改善 JCT，或者收益被决策开销和最坏情况恶化抵消，就停止继续扩大模型。

我的判断是：这条路线值得试，但应以成本敏感学习为主、普通行为克隆为对照，而不是反过来。

理论上的竞争比或近似比，是相对于某个指定问题的最优解给出最坏情况保证；它不意味着算法在所有实验实例中都比 PDRS 更快。

下一阶段三线裁定（基于 commit 8cc571d）。

一、P3 正确性收尾。 接受 GPU 测量采集，暂不接受完整共驻动态模型已经校准。只做 CPU 分析：修复 colocation_p3v2_analysis.json 中 NaN 导致的非法 JSON；使用实际 generate 起点计算偏移；正确处理 P-2 T2 的两次完成顺序反转；重新审查 piecewise/sticky/onetime 模型的公平拟合；给出局部 decode 步时恢复比值的逐轮分布与有效采样数量。继续保留 A1b FAIL，不覆盖 v7，不执行共驻 Headroom。

二、Phase-aware 模型研究。 仅批准独立诊断版本。先明确 prefill/decode 边界的测量定义、host token 时间与 GPU kernel 时间的区别、相位干扰参数可辨识性，以及 3 个实测组合无法覆盖完整 11-cell 动态空间的限制。先交参数契约、拟合/验证划分和 CPU 原型，不修改正式模拟器。

三、Student Feasibility Gate。 只使用调度 train 来源，冻结状态采样规则，按同一可见前缀构造多个兼容未来，计算全合法动作相对 PDRS 的配对成本。比较 Student-BC、Student-Cost、Student-Rank 三类轻量模型，输入严格限制为决策时可见信息。报告开天眼标签的条件不一致性、条件动作优势、episode-grouped 验证、状态识别能力及完整在线 DES 闭环 JCT。模型选择与门控阈值必须在训练侧完成，禁止触碰 Arrival-Holdout。先提交 50–100 状态试点与预计 CPU 预算，再决定是否扩量；若无可学的条件收益或无稳定闭环改善则停止。

四、理论算法规划。 独立写一份不训练模型的 Problem Reduction Note：将 GPU 驻留映射到带容量与不同加载代价的 online caching，列出与 GreedyDual-Size、学习增强缓存、Metrical Task Systems、经典链式完成时间调度的假设差异。区分可直接继承的已有定理、需要重新证明的结论与无法证明的完整 DES 性质。重点评估两 GPU、多模型驻留、活跃模型保护和冷加载开销是否可以在有限子问题中定义严格竞争比。先交问题定义与证明候选，不执行大型算法实验。

五、研究纪律。 三线不共享未冻结的性能结论；不为获得正收益修改物理 profile、测试分布或验证规则。所有新方法必须明确其超越已有工作的机制。共驻 A2/A3/B 与正式 v7 变更仍需独立申请。现有 Arrival-Holdout 保持封存。

七、最终研究方向建议

如果按“与最初课题一致”“是否能形成新方法”“资源投入是否可控”三个条件综合判断，我会这样排序：

第一优先：鲁棒预测增强的 GPU 模型驻留调度

这是最自然地把“未来信息”与实际跨时间资源成本联系起来的方向。以在线缓存理论为基础，解决有限显存、模型加载、错误预测以及多 GPU 资源约束之间的关系。

第二优先：成本敏感学生调度器

工程上最容易开展短周期验证，能利用已经积累的 DES、反事实数据生成和 PDRS 基线。但必须先证明条件收益可学习，不能因为可以无限生成开天眼标签，就直接启动大规模模仿训练。

第三优先：相位感知共驻执行模型

P3 的物理证据值得保留，甚至可能构成独立系统研究的一部分。但它目前更适合作为支撑可靠调度实验的基础设施贡献，而不是在没有调度收益证据时直接上升为论文主创新点。

我认为目前最值得保留的核心研究问题可以进一步收紧为：

在具有模型加载和有限驻留容量的在线 Agent 工作流中，能否设计一种即使未来预测错误也具有鲁棒性能、预测准确时又能降低请求完成时间的 GPU 调度机制？

这个问题的优势，是数学性质与未来信息消费可以形成一个统一方法：先有一个不依赖预测也可靠的基线，再在明确可获益的资源决策上利用预测，而不是依赖一个能力强但行为不可解释的神经网络来弥补整个调度系统。

它仍需实验证明 Headroom 和方法收益，但比继续增加 MILP 约束、AV 特征或学生模型容量，有更清晰的研究边界和停损机制。
